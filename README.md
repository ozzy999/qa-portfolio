# QA Portfolio — Ozzy

Dokumentasi proses belajar saya bertransisi karier menjadi QA Engineer (manual & automation testing), disusun secara terstruktur dan dipraktikkan langsung, bukan sekadar teori.

## Latar Belakang

Sebelumnya saya memiliki basic IT dan pernah menjadi mentor front-end web, dengan pemahaman dasar SQL. Saat ini saya fokus mempelajari QA Engineering secara mendalam — mencakup manual testing, test automation, dan tools kolaborasi tim (Jira, Git) — dengan target karier di posisi QA Engineer, termasuk peran yang menggabungkan manual dan automation testing di perusahaan fintech.

## Struktur Repository

| Folder | Isi |
|---|---|
| [`fase-1-manual-testing/`](./fase-1-manual-testing) | Fondasi manual testing: test plan formal, test case dengan prioritas berbasis risk analysis (impact × likelihood), exploratory testing charter, dan bug report profesional. Studi kasus disusun menyerupai fitur fintech (transfer dana). |
| [`qa-practice-sandbox/`](./qa-practice-sandbox) | Sandbox aplikasi fintech simulasi ("Dompetin") sebagai lingkungan latihan blind testing — saya menguji aplikasi ini hanya berbekal dokumen spesifikasi produk, tanpa diberi tahu di mana letak bug, persis seperti kondisi kerja QA sungguhan. Berhasil menemukan 13 bug valid secara mandiri. |

## Teknik & Konsep yang Dipraktikkan

- Software Testing Life Cycle (STLC)
- Equivalence Partitioning, Boundary Value Analysis, Decision Table Testing
- Risk-Based Test Prioritization (Impact × Likelihood)
- Exploratory Testing (Session-Based Charter)
- Penulisan bug report profesional (Severity vs Priority)

## Progres Selanjutnya

Repository ini akan terus diperbarui seiring saya lanjut ke tahap berikutnya: penulisan skenario Gherkin/BDD, workflow Jira & Git, hingga test automation menggunakan Playwright.
